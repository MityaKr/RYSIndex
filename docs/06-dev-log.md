# Журнал разработки

Ночная автономная сессия 09.11.2026. Решения, принятые без автора (он спал), помечены «решение».

## Решения без автора

- Слой JEI: мост поверх установленного JEI (вариант A из `05-competitors.md`). JEI необязателен: без него работают ванильные категории.
- Интерфейс JEI отключается штатным API `IJeiFeatures.disableJeiGui()`, без миксинов во внутренности JEI (у EMI для этого миксин в `PluginCaller`). Отключается настройкой `replaceJeiInterface`.
- Пакет `works.repka.ryscope`.
- Проект: `common/` (чистый Minecraft через NeoForm, без API загрузчика) + `neoforge/`. Общий код подключается в `neoforge` исходниками, jar один.
- API JEI для компиляции: 19.64.0.455 (версия из тестового инстанса), это же минимальная поддерживаемая.
- Тексты для игроков (en_us, ru_ru) написаны как черновик, автор их ещё не смотрел.

## База (MVP, этап 1 дорожной карты)

Сделано и проверено автотестом в игре:

- Снимок данных и индекс в фоновом потоке `RYScope-Index`. В главном потоке один короткий шаг: сбор креативных вкладок (и только когда нет JEI).
- Поиск в потоке `RYScope-Search`: подстрока, ранжирование, одна опечатка, чужая раскладка, транслит, несколько языков, `@мод #тег $подсказка *id /regex/ -исключение "фраза" a|b`, операторы `uses: from: in: craftable almost`.
- Панель списка справа с плавной прокруткой и виртуальным рендером, закладки слева, подсветка синтаксиса в поле поиска.
- Карточка рецептов: вкладки категорий, страницы, режимы «Рецепты / Использования», история переходов, подсветка недостающих ингредиентов.
- Свои раскладки: верстак, печь, плавильня, коптильня, костёр, камнерез, кузнечный стол.
- Перенос в слоты без серверной части: пакет книги рецептов, если рецепт открыт, иначе клики. Shift = максимум.
- Мост JEI: ингредиенты всех типов, категории, рецепты, катализаторы, перенос через обработчики JEI, ответы модам на запросы «что под курсором» и «покажи рецепты».
- Темы Slate, Vanilla Refined, Glass из JSON в ресурспаке, перечитываются по F3+T. Скругления рисуются в пикселях экрана со сглаживанием.
- Линза: карточка по Alt в интерфейсе и в мире (блок или существо под прицелом, чем добывается).

Замеры (dev-клиент, ваниль + JEI): индекс 10–170 мс, поиск около 0,1 мс на запрос, 1 691 ресурс, 1 259 своих рецептов, 15 категорий. С модами из инстанса For-Into-Mod (Innerworks, Jade, Patchouli): 22 категории, ошибок в журнале нет.

Чего в базе нет из этапа 1: кэша индекса на диск. При мосте он почти ничего не даёт: индекс строится за десятки миллисекунд, а дольше всего грузится сам JEI. Вернуться после замера в большой сборке.

## Автотест

`gradlew :neoforge:runAutotest` запускает клиент со свойством `ryscope.autotest`: мод сам создаёт мир, проходит по экранам, сохраняет скриншоты в `neoforge/run/screenshots` и закрывает игру. `-PnoJei` запускает без JEI, `-PextraMods=<папка>` подключает моды из папки.

## Цикл 7. JEI без установки и без фриза (09.11.2026, утро)

Запрос автора: убрать зависимость от JEI для игрока и оптимизировать.

Решение: JEI вложен в jar RYScope, а его запуск перенесён в фоновый поток. Свою реализацию API JEI с нуля не писал, причины ниже.

- ✅ Неизменённый JEI 19.70.0.469 лежит внутри нашего jar (`META-INF/jarjar`). Лицензия JEI это разрешает (MIT, текст в `META-INF/licenses`, сводка в `THIRD_PARTY.md`). Игрок ставит один файл. Если в сборке есть JEI новее, загрузчик берёт более новый.
- ✅ Запуск JEI идёт в потоке `RYScope-JEI`. Сам JEI грузит плагины в главном потоке: с Create, Mekanism и AE2 это 1,15 с замершей игры при входе в мир. Теперь главный поток не останавливается, а список предметов доступен сразу (по реестру) и дополняется, когда JEI готов.
- ✅ Страховка: если при фоновой загрузке JEI записал в журнал ошибку плагина, он перезапускается обычным способом, а в настройках ставится `asyncJeiFailed`. Проверено имитацией сбоя.
- ✅ Вмешательство во внутренности JEI одно: миксин в конструктор `StartEventObserver`, оборачивает два Runnable. При несовпадении версии не применяется, и JEI стартует как обычно.
- ✅ Модуль `prodtest`: проверка «как у игрока», в модах только собранный jar. `gradlew :prodtest:runAutotest`.

Замеры (собранный jar, отдельного JEI нет):

| Набор | Загрузка JEI | Где | Ошибок плагинов |
|---|---|---|---|
| Create + Mekanism + AE2 | 1,18 с | фоновый поток | 0 |
| Innerworks + Jade + Patchouli | 0,73 с | фоновый поток | 0 |

Размер jar вырос с 0,33 до 4,6 МБ.

### Почему не своя реализация API JEI

- Время загрузки складывается из работы самих плагинов (Create 150 мс, Mekanism 100 мс) и ванильного плагина JEI. Своя реализация выполняла бы те же плагины; выигрыш был бы только на ванильной части, а фриз снимается переносом в фон в обоих случаях.
- Тяжёлые части JEI (интерфейс, дерево поиска) уже отключены штатным `disableJeiGui`.
- Главная жалоба игроков на EMI как раз неполная совместимость слоя с плагинами. Вложенный JEI даёт совместимость полную, включая моды, которые лезут во внутренности JEI.
- Объём своей реализации: около 200 интерфейсов API, оценочно 6–10 тысяч строк и долгий хвост несовместимостей.

Что не проверено: большая сборка (сотни модов), где плагинов много и шанс встретить плагин, не переживающий фоновый поток, выше; поведение при JEI новее вложенного.

## Цикл 9. Серверные стадии (09.11.2026)

Запрос автора: превратить стадии из подсказки в настоящий замок.

- ✅ Скрытие: пакет со списком рецептов подменяется для каждого игрока, рецепты закрытых стадий с `hidden` в него не попадают. Клиент о них не знает вовсе.
- ✅ Запрет: сетка крафта не выдаёт результат закрытого рецепта. Используется то же место, где игра проверяет правило `doLimitedCrafting`.
- ✅ Клиент получает описания и состояние пакетом `ryscope:stages`, причину отказа пакетом `ryscope:stage_notice`.
- ✅ Работает и для клиентов без мода: скрытие и запрет на стороне сервера, причина отказа приходит строкой над хотбаром.
- ✅ Поле `hint`: подсказка автора сборки, как открыть стадию. Клиент знает названия только уже показанных ему достижений, поэтому без подсказки строка «как открыть» может быть пустой.

Проверено автотестом в одиночной игре (встроенный сервер), на dev-клиенте и на собранном jar с Create, Mekanism и AE2:

| Проверка | Результат |
|---|---|
| Рецепты скрытой стадии у клиента при входе | нет |
| Результат закрытого рецепта в верстаке | пусто |
| После `/ryscope stage grant` результат в верстаке | есть |
| После получения достижения скрытые рецепты у клиента | есть |
| После отзыва достижения (мир с прошлого запуска) скрытые рецепты у клиента | нет |

Найдено и исправлено по ходу: сервер не реагировал на отзыв достижения; сообщение о причине отказа было перекрыто окном верстака.

Вмешательств в код игры два (миксины): отправка пакетов сервером и расчёт результата в `CraftingMenu`. Оба с `require = 0`: если в другой версии игры место изменится, мод загрузится, но замок работать не будет. Отдельной проверки на этот случай нет.

Не проверено: выделенный сервер и несколько игроков с разным состоянием; клиент без мода; `/reload` при игроках в сети. Не сделано: запрет в печах, кузнечном столе, камнерезе и машинах модов.

## Цикл 10. Запрет в ванильных блоках (09.11.2026)

Запрос автора: распространить запрет на печи, кузнечный стол и камнерез.

- ✅ Кузнечный стол: результат закрытого рецепта не выдаётся.
- ✅ Камнерез: результат закрытого рецепта не выдаётся; рецепты скрытых стадий убраны из серверного списка, иначе номера рецептов у клиента и сервера разошлись бы.
- ✅ Печь, плавильня, коптильня: закрытый рецепт не плавится, топливо не тратится. Решение по игроку, который открывал печь последним; его UUID хранится в данных блока. Для игрока не в сети берётся состояние на момент последнего входа (хранится вместе с миром).
- ✅ Проверка при старте сервера: все ли вмешательства в код игры применились. Если нет, в журнале ошибка с перечнем мест. Это закрывает оговорку из цикла 9.

Проверено автотестом на dev-клиенте и на собранном jar с Create, Mekanism и AE2:

| Проверка | Результат |
|---|---|
| Камнерез, закрытый рецепт | пусто |
| Камнерез, открытый рецепт из того же списка | есть |
| Кузнечный стол, закрытый рецепт | пусто |

| Печь, закрытый рецепт | не горит, уголь не тратится |

Вмешательств в код игры теперь пять (серверная часть) плюс одно в JEI (клиент).

Не сделано: костёр, автоверстак (crafter), варочная стойка, машины модов. Не проверено: выделенный сервер, игрок не в сети как хозяин печи, клиент без мода.
