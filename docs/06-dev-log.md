# Журнал разработки

Ночная автономная сессия 09.11.2026. Решения, принятые без автора (он спал), помечены «решение».

## Решения без автора

- Слой JEI: мост поверх установленного JEI (вариант A из `05-competitors.md`). JEI необязателен: без него работают ванильные категории.
- Интерфейс JEI отключается штатным API `IJeiFeatures.disableJeiGui()`, без миксинов во внутренности JEI (у EMI для этого миксин в `PluginCaller`). Отключается настройкой `replaceJeiInterface`.
- Пакет `works.repka.ryscope`.
- Проект: `common/` (чистый Minecraft через NeoForm, без API загрузчика) + `neoforge/`. Общий код подключается в `neoforge` исходниками, jar один.
- API JEI для компиляции: 19.42.0.379, это же минимальная поддерживаемая (см. цикл 11; до него была 19.64.0.455).
- Тексты для игроков (en_us, ru_ru) написаны как черновик, автор их ещё не смотрел.

## База (MVP, этап 1 дорожной карты)

Сделано и проверено автотестом в игре:

- Снимок данных и индекс в фоновом потоке `RYScope-Index`. В главном потоке один короткий шаг: сбор креативных вкладок (и только когда нет JEI).
- Поиск в потоке `RYScope-Search`: подстрока, ранжирование, одна опечатка, чужая раскладка, транслит, несколько языков, `@мод #тег $подсказка *id /regex/ -исключение "фраза" a|b`, операторы `uses: from: in: craftable almost`.
- Панель списка справа с плавной прокруткой и виртуальным рендером, закладки слева, подсветка синтаксиса в поле поиска.
- Карточка рецептов: вкладки категорий, страницы, режимы «Рецепты / Использования», история переходов, подсветка недостающих ингредиентов.
- Свои раскладки: верстак, печь, плавильня, коптильня, костёр, камнерез, кузнечный стол.
- Перенос в слоты без серверной части: пакет книги рецептов, если рецепт открыт, иначе клики. Shift = максимум.
- Мост JEI: ингредиенты всех типов, категории, рецепты, катализаторы, перенос через обработчики JEI, ответы модам на запросы «что под курсором» и «покажи рецепты».
- Темы Slate, Vanilla Refined, Glass из JSON в ресурспаке, перечитываются по F3+T. Скругления рисуются в пикселях экрана со сглаживанием.
- Линза: карточка по Alt в интерфейсе и в мире (блок или существо под прицелом, чем добывается).

Замеры (dev-клиент, ваниль + JEI): индекс 10–170 мс, поиск около 0,1 мс на запрос, 1 691 ресурс, 1 259 своих рецептов, 15 категорий. С модами из инстанса For-Into-Mod (Innerworks, Jade, Patchouli): 22 категории, ошибок в журнале нет.

Чего в базе нет из этапа 1: кэша индекса на диск. При мосте он почти ничего не даёт: индекс строится за десятки миллисекунд, а дольше всего грузится сам JEI. Вернуться после замера в большой сборке.

## Автотест

`gradlew :neoforge:runAutotest` запускает клиент со свойством `ryscope.autotest`: мод сам создаёт мир, проходит по экранам, сохраняет скриншоты в `neoforge/run/screenshots` и закрывает игру. `-PnoJei` запускает без JEI, `-PextraMods=<папка>` подключает моды из папки.

## Цикл 7. JEI без установки и без фриза (09.11.2026, утро)

Запрос автора: убрать зависимость от JEI для игрока и оптимизировать.

Решение: JEI вложен в jar RYScope, а его запуск перенесён в фоновый поток. Свою реализацию API JEI с нуля не писал, причины ниже.

- ✅ Неизменённый JEI 19.70.0.469 лежит внутри нашего jar (`META-INF/jarjar`). Лицензия JEI это разрешает (MIT, текст в `META-INF/licenses`, сводка в `THIRD_PARTY.md`). Игрок ставит один файл. Если в сборке есть JEI новее, загрузчик берёт более новый.
- ✅ Запуск JEI идёт в потоке `RYScope-JEI`. Сам JEI грузит плагины в главном потоке: с Create, Mekanism и AE2 это 1,15 с замершей игры при входе в мир. Теперь главный поток не останавливается, а список предметов доступен сразу (по реестру) и дополняется, когда JEI готов.
- ✅ Страховка: если при фоновой загрузке JEI записал в журнал ошибку плагина, он перезапускается обычным способом, а в настройках ставится `asyncJeiFailed`. Проверено имитацией сбоя.
- ✅ Вмешательство во внутренности JEI одно: миксин в конструктор `StartEventObserver`, оборачивает два Runnable. При несовпадении версии не применяется, и JEI стартует как обычно.
- ✅ Модуль `prodtest`: проверка «как у игрока», в модах только собранный jar. `gradlew :prodtest:runAutotest`.

Замеры (собранный jar, отдельного JEI нет):

| Набор | Загрузка JEI | Где | Ошибок плагинов |
|---|---|---|---|
| Create + Mekanism + AE2 | 1,18 с | фоновый поток | 0 |
| Innerworks + Jade + Patchouli | 0,73 с | фоновый поток | 0 |

Размер jar вырос с 0,33 до 4,6 МБ.

### Почему не своя реализация API JEI

- Время загрузки складывается из работы самих плагинов (Create 150 мс, Mekanism 100 мс) и ванильного плагина JEI. Своя реализация выполняла бы те же плагины; выигрыш был бы только на ванильной части, а фриз снимается переносом в фон в обоих случаях.
- Тяжёлые части JEI (интерфейс, дерево поиска) уже отключены штатным `disableJeiGui`.
- Главная жалоба игроков на EMI как раз неполная совместимость слоя с плагинами. Вложенный JEI даёт совместимость полную, включая моды, которые лезут во внутренности JEI.
- Объём своей реализации: около 200 интерфейсов API, оценочно 6–10 тысяч строк и долгий хвост несовместимостей.

Что не проверено: большая сборка (сотни модов), где плагинов много и шанс встретить плагин, не переживающий фоновый поток, выше; поведение при JEI новее вложенного.

## Цикл 9. Серверные стадии (09.11.2026)

## Цикл 19: поиск мода по названию и шаблон постройки AE2 (17.11.2026)

Замечания автора, версия 0.2.3.

Поиск `@мод`. Раньше `@` сравнивал первое слово запроса с id и названием мода как подстроку, поэтому мод с пробелом или двоеточием в названии («Applied Energistics 2», «Actually Additions: Tiers») находился только по одному слову. Теперь у записи индекса есть ключи мода `SearchEntry.modKeys`: id мода, его название, мод, к которому предмет относит JEI, и псевдонимы мода, каждый в сжатом виде (`Query.squash`: нижний регистр, только буквы и цифры). Запрос `@` сжимается так же и ищется подстрокой в любом ключе. Граница запроса: после `@слово` следующие слова присоединяются к названию мода, пока вместе они ещё входят в чей-то ключ (список ключей всех модов индекс передаёт в `Query.setModKeys`). Слово из одной пунктуации («:») присоединяется всегда. Так `@applied energistics 2 cable` это мод AE2 и слово «cable», `@ae2 cable` то же самое. Кавычки `@"…"` задают границу явно, `mod:` работает так же, как `@`. Выбор против варианта «до следующего `@` или `#`»: тот ломал привычное `@ae2 cable`. Неоднозначный случай: если следующее слово продолжает название другого мода (`@ae2 wireless` входит в «AE2 Wireless Terminals»), оно уйдёт в название мода; разделить можно кавычками или порядком слов (`wireless @ae2`). Тест `SearchTest.modNamesWithSpacesAndPunctuation`.

«+» у превью мультиблока MMR. `StructureRecipeView` считает постройку по умолчанию: для каждой буквы структуры блок, прописанный в ключе явно (`BlockIngredient.getNonTagStacks`), без блоков модификаторов (`ModifierReplacement.getIngredient`, в RepYS это ядра разгона); люки входа, выхода, энергии и параллельности в машинах RepYS приходят тегами и поэтому не попадают. Ключ только из тега даёт первый по id блок тега. Количество: сколько раз буква встречается в структуре, как в списке блоков превью MMR (`DynamicMachine.getStacks`). Контроллер не входит. Выход шаблона: предмет машины, как его показывает MMR (`ControllerItem.makeMachineItem`: контроллер с id машины в компоненте `modular_machinery_reborn:machine`). Отдельного чертежа машины в MMR 3.0.25 нет: `modular_machinery_reborn:blueprint` без компонентов, это простой предмет. Запись идёт тем же помощником AE2, что и у JEI-интеграции AE2 (`ae2jeiintegration`, `EncodePatternTransferHandler`) и у прежнего переноса RYScope: `EncodingHelper.encodeProcessingRecipe`, терминал переходит в режим обработки, слоты заполняются пакетами AE2. Входы в полном количестве (шаблон AE2 принимает больше стопки). Входов у шаблона обработки 81 (`PatternEncodingLogic`), у машин RepYS от 3 до 9 видов блоков; если разных блоков больше, «+» ничего не пишет и говорит, что не помещается. Без открытого терминала кодирования шаблонов «+» неактивен с подсказкой (`RecipeView.showsTransfer`, `transferUnavailable`). Автотест `fb17`.

Куча после GC каждые две «минуты» и в меню после выхода, там же гистограмма классов через jcmd (`logs/ryscope-leak-hist-N.txt`). Выход в меню идёт через `Minecraft.tell`: сам выход крутит тики игры, пока встроенный сервер не остановится, и шаг автотеста из обработчика тика выполнился бы повторно изнутри себя.

Внутри сессии куча ровная (4617–4694 МБ на копии RepYS). Между сессиями в одиночной игре она растёт на 0,5–1,1 ГБ за вход, но не из-за нас: каждый встроенный сервер держит applied_kjs (`AppliedKJSServerState.INSTANCES`, WeakHashMap, значение держит ключ). Цепочка до корня снята JFR (`jdk.OldObjectSample`, `path-to-gc-roots=true`).

Своё, исправлено:
- После выхода из мира индекс строился заново по покинутому миру: пока останавливается встроенный сервер, игра крутит тики со старым миром и игроком (`Minecraft.disconnect`, `runTick` в ожидании сервера), и `onClientTick` видел пустой индекс; второй запрос шёл из остановки JEI (`Foreign.set(null)`). Теперь `Indexer.clear` закрывает индекс до первого тика без мира (`Indexer.reopen`).
- Прежний снимок держали `SearchService.warmFor` и панели `Overlay` (список, ключи подсветки и закладок, кеш тегов). В меню жили два снимка: SearchEntry 60 246, ItemRes 1,83 млн. После правки в меню ни одного, куча в меню 4389 МБ против 4710.
- `Storages` не чистился при выходе (тик без игрока не наступает), и сеть беспроводного терминала AE2 прошлого мира подмешивалась к следующему. `Ae2Terminal.active` держал меню терминала после выхода.
- `Operators.MEMO` держал до восьми прежних снимков после переиндексации: теперь очищается при новом снимке.

### Сведения JEI во вкладке «Справка»

Просьба автора: «Сведения» JEI (`addInformation`, например про зачарование «Захват» у яиц призыва) показывались в «Рецептах» окном JEI: моноширинный шрифт в серой рамке со своей прокруткой. А вкладка «Справка» всегда была серой, потому что страниц `ryscope_help` в сборке нет.

- Новый `content/HelpPage`: страница справки нашим видом. Слева сверху предмет на плашке слота (в карточке сам предмет карточки, если он среди целей страницы, иначе цели по очереди), справа колонка текста шрифтом темы (`Draw.label`, 12 px макета, строка 10 единиц, между абзацами 4). Перенос по словам с кусками разного тона в одной строке (обычный `text.body`, выделенный `text.primary`, ссылка `accent`), слово шире колонки режется по буквам. Предупреждение на подложке `state.warn` с полосой слева, предметы рядами под абзацем по ширине колонки. Высоты больше не обрезаются на 150: длинную страницу листает колесо карточки.
- `HelpView` (страницы из JSON) переведён на `HelpPage`: раньше он рисовал ванильным шрифтом и резал всё ниже 150 единиц.
- `jei/JeiInfoView`: рецепт `IJeiIngredientInfoRecipe` превращается в ту же страницу. Строка описания JEI это абзац, пустые строки дают промежуток, цвет и жирность текста мода становятся выделенным тоном. `JeiBridge` отдаёт такие рецепты в категории `ryscope:help` (одна на всё, `HelpContent.category()`), поэтому они сливаются с нашими страницами в одну группу: сначала наши страницы, следом сведения JEI, каждая своим блоком, листаются как рецепты.
- Карточка: справка берётся только из поиска рецептов (раньше и страница, и сведения находились ещё и как использование и считались дважды). Сведения больше не числятся рецептом крафта: счётчики «Рецептов» и «Использований» без них, дерево крафта не берёт сведения за способ получить предмет. Вкладка «Справка» активна, когда есть страница или сведения, иначе серая. Предмет, у которого есть только справка (яйцо призыва), открывается на ней с уведомлением «Рецептов нет, показана справка». У страниц справки нет звезды закладки, название в строке категории не ссылка, заголовок категории «О предмете», чтобы не повторять вкладку.
- Юнит-тест `HelpPageTest`: слова из кусков разного тона, перенос, смена тона в строке, длинное слово.
- Автотест `help` (`gradlew :prodtest:runAutotest -PrunDir=run-repys -Pautotest=help -Pheap=8G --offline`): яйцо призыва тихони (карточка открывается на «Справке», сведения JEI нарисованы; темы slate, glass, vanilla; колесо; подсказка предмета страницы), поршень со своей страницей из примеров автотеста (`config/ryscope/help/piston.json`, наша страница первая), предмет без справки (вкладка серая), узкое окно 960×540.
