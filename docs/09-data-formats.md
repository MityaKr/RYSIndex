# Форматы данных для авторов сборок и модов

Всё, что описывается данными, без Java. Раскладки категорий вынесены в отдельный документ: `07-layouts.md`.

| Что | Ресурспак или jar мода | Папка сборки |
|---|---|---|
| Раскладки категорий | `assets/<ns>/ryscope_layouts/*.json` | нет |
| Группы предметов | `assets/<ns>/ryscope_groups/*.json` | нет |
| Темы | `assets/<ns>/ryscope_themes/*.json` | нет |
| Страницы справки | `assets/<ns>/ryscope_help/*.json` | `config/ryscope/help/*.json` |
| Стадии | `assets/<ns>/ryscope_stages/*.json` | `config/ryscope/stages/*.json` |

Данные перечитываются при перезагрузке ресурсов (F3+T).

## Страницы справки

```json
{ "target": "minecraft:piston",
  "body": [
    { "p": "Поршень толкает до 12 блоков. Положите на него [[item:minecraft:slime_ball]], чтобы получить [[item:minecraft:sticky_piston]]." },
    { "warn": "Обсидиан и коренную породу сдвинуть нельзя." },
    { "items": ["minecraft:lever", "minecraft:redstone_torch"] }
  ] }
```

- `target`: id предмета, `#тег` или массив. Страница появляется вкладкой «Справка» и в рецептах, и в использованиях этих предметов.
- `p`: абзац. Значением может быть ключ перевода.
- `warn`: предупреждение, выделяется полосой и фоном.
- `items`: ряд предметов.
- Ссылки в тексте: `[[item:id]]` подставляет название предмета и показывает сам предмет под абзацем (по нему можно кликнуть); `[[что-угодно:цель|подпись]]` показывает подпись.

Ограничения: высота страницы до 150 пикселей GUI, лишнее обрезается; трёхмерных схем мультиблоков и ссылок на Patchouli нет.

## Стадии

```json
{ "name": "Алмазный век",
  "order": 2,
  "advancement": "minecraft:story/mine_diamond",
  "hint": "Добудьте алмаз",
  "hidden": false,
  "enforce": true,
  "items": ["minecraft:diamond_pickaxe", "#minecraft:beds", "@create"],
  "recipes": ["minecraft:jukebox", "/create:mixing\\/.*/"],
  "categories": ["create:mixing"] }
```

| Поле | Смысл |
|---|---|
| `advancement` | достижение, которое открывает стадию. Без поля стадия открыта всегда |
| `hint` | подсказка игроку, как открыть стадию: текст или ключ перевода |
| `items` | id предмета, `#тег` или `@мод` |
| `recipes` | id рецепта или регулярное выражение в косых чертах |
| `categories` | на клиенте id категории, на сервере id типа рецепта (обычно совпадают) |
| `hidden` | сервер не отправляет игроку рецепты стадии, пока она закрыта. По умолчанию `false` |
| `enforce` | сервер не даёт выполнить закрытый рецепт в сетке крафта. По умолчанию `true` |

Рецепт относится к стадии, если подошёл его id, тип или результат (результат проверяется по `items`).

### Где лежат описания и кто решает

| Где | Кто читает | Что даёт |
|---|---|---|
| `data/<ns>/ryscope_stages/*.json` в датапаке | сервер | настоящий замок: скрытие и запрет крафта |
| `config/ryscope/stages/*.json` | сервер и клиент | то же; в одиночной игре сервер встроенный |
| `assets/<ns>/ryscope_stages/*.json` в ресурспаке | только клиент | подсказка с замком, ничего не запрещает |

Если сервер прислал стадии, клиент показывает его решение и свои файлы не использует.

### Что делает сервер

- Считает стадию открытой, если выполнено достижение или стадия выдана командой. Отзыв достижения закрывает её обратно.
- Не отправляет игроку рецепты закрытых стадий с `"hidden": true`. Работает и для клиентов без мода: рецептов нет ни в книге рецептов, ни в JEI, ни у нас.
- Не выдаёт результат в верстаке и в сетке инвентаря для закрытого рецепта с `enforce`. Если результат считает другой мод (например, FastWorkbench), он может быть показан в слоте, но забрать его нельзя. Клиенту с модом причина показывается поверх окна, остальным строкой над хотбаром.
- Когда стадия открывается, досылает игроку рецепты; JEI перечитывает их в фоне.

Команды (уровень прав 2):

```
/ryscope stage list
/ryscope stage grant <игроки> <id стадии>
/ryscope stage revoke <игроки> <id стадии>
```

Id стадии из папки сборки выглядит как `config:<имя файла>`, из датапака как `<ns>:<имя файла>`. Выданные стадии хранятся вместе с миром.

### Что видит игрок

Закрытый предмет виден в списке с замком (или скрыт, если включена настройка). Рецепт закрытой стадии приглушён и подписан названием стадии и подсказкой. Поиск: `locked`, `unlocked`, `stage:название`.

Другой мод может открыть стадию на клиенте вызовом `Stages.setUnlocked(id, true)`; на серверное решение это не влияет.

### Чего сервер не делает

- Запрет действует в ванильных блоках: верстак и сетка инвентаря, кузнечный стол, камнерез, печь, плавильня, коптильня, костёр, автоверстак и варочная стойка. Машины модов закрытый рецепт выполнят. Скрытие (`hidden`) от этого не защищает: оно убирает рецепт из показа, а не из игры.
- Предметы стадии не отбираются и не блокируются в использовании.

### Как запрет работает в блоках, которые работают сами

Печь, автоверстак и варочная стойка работают без игрока, поэтому решение принимается по тому, кто открывал блок последним:

- стадия закрыта у этого игрока: закрытый рецепт не выполняется (в печи топливо не тратится, автоверстак ведёт себя так, будто рецепта нет, варка не начинается);
- игрок не в сети: берётся его состояние на момент последнего входа;
- блок никто не открывал (например, его кормит воронка): запрета нет, приписать работу некому.

Костёр устроен проще: еду на него кладёт игрок, и продукт закрытого рецепта у игрока с закрытой стадией просто не кладётся.

У зелий нет рецептов с id, поэтому для варочной стойки стадия проверяется по результату: поле `items` должно называть то, что получится. Все зелья это один предмет `minecraft:potion`, так что закрыть можно зельеварение целиком, но не отдельное зелье.

Это значит, что игрок с открытой стадией может запустить печь для игрока с закрытой. Для стадий по командам или кланам это ожидаемо, для личной прогрессии стоит иметь в виду.

### Проверка при старте

При запуске сервера мод проверяет, что все вмешательства в код игры на месте, и пишет в журнал одну из строк:

```
Замки стадий установлены: пакет рецептов, верстак, слот результата, кузнечный стол, камнерез, печи, костёр, автоверстак, варочная стойка
Замки стадий НЕ установлены в: [...]
```

Вторая строка означает, что версия игры или загрузчика отличается от той, под которую собран мод, и в перечисленных местах закрытые рецепты выполняются.

## Группы предметов

```json
{ "name": "ryscope.group.wool", "tags": ["minecraft:wool"], "items": ["minecraft:potion"], "match": "minecraft:.*_concrete" }
```

Любое из трёх полей относит предмет к группе: тег, id или регулярное выражение по полному id. Группа сворачивается, если в списке у неё три предмета и больше.

## Время и энергия рецептов

Нужны планировщику и сравнению маршрутов. Берутся из раскладки категории:

```json
{ "for": ["create:crushing"], "time": "processing_time", "time_default": 100, "energy_per_tick": 0 }
```

- `time`: путь к числу тиков в JSON рецепта; `time_default`: значение, если поля нет.
- `energy_per_tick`: расход в FE за тик работы машины.

У ванильной печи, плавильни, коптильни и костра время берётся из рецепта. У рецептов без этих данных (верстак, рецепты из плагинов JEI) машины не считаются: в планировщике они помечены «вручную или нет данных о времени».

Встроенные значения для Mekanism и AE2 приблизительные (200 тиков и 20 FE/т для машин Mekanism без улучшений), проверять по своей сборке.

## Единицы энергии

Игрок выбирает единицы в настройках: FE, RF, J, EU. Пересчёт встроен: 1 FE = 1 RF = 2,5 J = 0,25 EU. Своих единиц добавить данными пока нельзя.

## Отчёты и выгрузка

Кнопки в настройках:

- «Отчёты для автора сборки» пишет в `config/ryscope/reports`: `conflicts.json` (одинаковые входы в одной категории дают разное), `duplicates.json`, `no_known_source.json` (предметы без рецепта и без известного источника).
- «Выгрузить предметы и рецепты» пишет `items.json` и `recipes.json` в `config/ryscope/export`.

Конфликты это кандидаты, а не приговор: туда попадают, например, рецепты пилы Create, где результат выбирается фильтром, и рецепты, различающиеся только компонентами ингредиента. Рецепты, которые рисуют плагины JEI, в отчёты и выгрузку не попадают.

В карточке рецептов: Ctrl+C копирует id предмета или рецепта под курсором, Ctrl+Shift+C копирует весь рецепт в JSON.
