# Что игрокам нравится и не нравится во вьюерах рецептов

Собрано 09.11.2026 из открытых источников за 2024–2026 годы. Затем я прошёл по своему интерфейсу как игрок (раздел 6).

## Оговорки

- Reddit напрямую не отдаётся: треды r/feedthebeast читались через архив Arctic Shift. r/ModdedMinecraft и r/fabricmc получить не удалось.
- Комментарии CurseForge требуют входа, вместо них взяты отзывы moddex.gg.
- Выборка небольшая: около 10 тредов Reddit и issues трёх репозиториев через GitHub API. Счётчики лайков приблизительные.
- Уверенность: **Ч** встречается часто, **В** встречается в 1–2 источниках, **Е** единичное мнение.

## 1. Что ценят

**JEI.** Лучшая совместимость: большинство модов делают плагин только под него (Ч). Простой привычный интерфейс (В). По Esc возвращает в квестбук, откуда открыли рецепт (В). Обновляется на новые версии раньше EMI (Е).

**EMI.** Дерево крафта как калькулятор с учётом инвентаря (Ч). Быстрый крафт из просмотра рецепта и рецепты по умолчанию (Ч). История просмотров (В). Настраиваемые панели (Ч). Показ тегов (В).

**REI.** Сворачиваемые группы предметов (Ч). Глубокая настройка и удобное меню конфига (В). Копирование id клавишей (В). Выделение рамкой и «выбрать все результаты поиска» (Е).

## 2. На что жалуются

**JEI.** Долгий старт в больших сборках: существует минимум четыре сторонних мода-ускорителя (Ч). После 1.21.2 не работает на сервере без серверной части (Ч). Медленные порты, один мейнтейнер (Ч). Нет групп, скрывать предметы приходится по одному или скриптами (Ч). Нет дерева, тегов, истории (В).

**EMI.** Неполная совместимость с плагинами JEI; встроенный слой медленный и ест память, почти всегда советуют TMRV (Ч). После входа в мир несколько секунд недоступен (В). Скрытие большого числа предметов даёт минуты перезагрузки (В). Одно дерево за раз, не переживает перезапуск (Ч). Закрывает всё вместо возврата в FTB Quests (В). Свои клавиши отдельно от общего меню управления (В). Перегруженный конфиг без справки (В).

**REI.** Поиск в больших сборках занимает секунды, первое открытие инвентаря подвисает (В). Назойливое предупреждение на серверах 1.21.2+ (Ч). Слабая поддержка и отставание по версиям (В).

## 3. Чего просят и не получают

| Запрос | Уверенность | Состояние в RYScope |
|---|---|---|
| Группы и папки предметов, сворачивание | Ч, самый заплюсованный | цикл 5 |
| Несколько деревьев с суммой сырья, сохранение | Ч | доска целей: несколько целей, сохраняются; общей суммы нет |
| Папки и страницы закладок | Ч | нет |
| Фильтр «только то, что можно скрафтить» | Ч | есть оператор `craftable`, нет кнопки |
| Скрытие неоткрытых рецептов, рантайм-API скрытия | Ч | нет (стадии из концепта) |
| Массовое скрытие по моду или регулярке | В | цикл 5 |
| Клиентский fallback на серверах без мода | Ч | есть для 1.21.1: рецепты приходят клиенту, перенос идёт кликами |
| Рецепт блока, на который смотришь | В | есть: линза |
| Чит-режим только в креативе | В | есть |
| Экспорт рецептов и предметов в JSON | В | цикл 6 |
| Сохранённые поиски | Е–В | нет |

## 4. Что важно авторам сборок

- Скрытие рецептов и категорий одним скриптом для всех вьюеров через KubeJS RecipeViewerEvents (В). У нас это приходит через JEI, но свои раскладки ванильных рецептов скрытие JEI пока не учитывают: цикл 5.
- Стадии и скрытие по прогрессу (В).
- Скрытие тысяч предметов без потери производительности (В).
- Покрытие JEI-плагинов: «без слоя совместимости у EMI нет большинства кастомных рецептов» (Ч).
- Время загрузки и память: по бенчмарку автора TMRV на ATM10 его слой даёт около 5 с против 20 с у встроенного слоя EMI и на 890 МиБ меньше (В, цифры самого автора).

## 5. Почему выбирают или не переходят

- На EMI переходят ради дерева, быстрого крафта и истории (Ч).
- На JEI остаются из-за совместимости, привычки и «EMI переусложнён» (Ч).
- Многие ставят оба, чтобы не выбирать (Ч).
- Выбор решает наличие сборки под нужную версию игры (В).

## 6. Мой проход как игрока

Что мешало и что уже исправлено этой же ночью:

- ✅ Неясно, что можно сделать с предметом в списке. Теперь при наведении подвал панели показывает клавиши: рецепты, использования, закладка, дерево.
- ✅ Очистить поиск можно было только правым кликом. Добавлен крестик.
- ✅ Красные метки «не хватает» и затемнение были на всех рецептах даже при простом просмотре и мешали читать. Теперь они есть только там, где рецепт можно разложить по слотам.
- ✅ В теме Glass кнопки были сплошь белыми: прозрачность из темы не применялась к фону. Исправлено.
- ✅ На экране 720p с GUI Scale 3 помещался один рецепт верстака. Карточка сжимается, помещаются два.

Что осталось и видно невооружённым глазом:

- Рецепты из JEI нарисованы на светло-серой подложке внутри тёмной карточки. Это цена полной совместимости; лечится только своими раскладками (см. `07-layouts.md`).
- Клавиши в подсказке линзы показаны буквами текущей раскладки клавиатуры (на русской раскладке «К», «Г», «Ф»).
- Список в правой панели узкий при GUI Scale 3 (5 колонок на 1280 px).

## 7. Выводы для RYScope

1. **Совместимость с плагинами JEI без установки JEI.** ✅ Закрыто в цикле 7: JEI вложен в jar мода, плагины грузятся в фоновом потоке. Память, которую занимает сам JEI, мы по-прежнему не контролируем.
2. Группы предметов и массовое скрытие: здесь можно обойти всех троих.
3. Дерево и доска целей уже закрывают две частые жалобы на EMI (одно дерево, не сохраняется).
4. Интерфейс по умолчанию надо держать минимальным, а клавиши в общем меню управления: так и сделано.
5. Серверы 1.21.2+ (рецепты больше не приходят клиенту) потребуют серверной части. Для 1.21.1 это не блокер.
