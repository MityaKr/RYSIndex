## Доступ к проекту RYScope

Тебе подключена папка `C:\Projects\RepYS\RYScope`.

* Она только для чтения. Ничего там не меняй, не коммить, не запускай там сборку и не трогай `prodtest/run-repys`: этим занимается другая сессия, и рабочее дерево может быть в середине правок.

* Папки `questscope/`, `ryspulse/`, `rysquests-companion/` внутри неё это концепты, не код RYScope.
* Если для экосистемы нужна правка в RYScope, не делай её сам. Напиши мне блок «Запрос к RYScope»: что нужно, зачем, какой контракт. Я передам.

## Что такое RYScope

Просмотрщик рецептов для Minecraft 1.21.1, NeoForge, modid `ryscope`, пакет `works.repka.ryscope`, конкурент JEI/EMI/REI. Рабочая версия 0.1.0, не опубликована. Fabric в конце, перед первой публикацией.

Главное устройство: JEI (MIT) вложен в наш jar, его интерфейс отключён штатно, рецепты модов берутся через его плагины и рисуются в нашей карточке. Свои раскладки есть для ванили, Create, Mekanism, AE2.

Что умеет: список с поиском в фоновом потоке (нечёткий, транслит, операторы), карточка рецептов с вкладками открытых предметов, Линза (Alt над чем угодно, в том числе в мире), дерево крафта (режим «Кратчайший», запас из инвентаря и хранилищ), план производства, сравнение маршрутов, доска целей поверх мира, закладки с папками, сохранённые поиски, серверные стадии с замками, перенос в терминалы AE2, перекраска серых окон рецептов под тему, панель кнопок FTB вместо их собственной.

Проверено на RepYS: 34 093 ресурса, 209 755 рецептов, 607 категорий, расхождений с JEI нет. Цифры и решения в `docs/06-dev-log.md`.

Читай в таком порядке: `README.md`, `docs/06-dev-log.md` (циклы 11–13), `docs/09-data-formats.md`, `docs/02-design.md`, потом код из разделов ниже.

## Что должно быть общим

**Вид.** Игрок не должен видеть шов между модами.

* Твой черновик темы в `docs/04-ui.md` расходится с рабочим форматом. Настоящий формат: `common/src/main/resources/assets/ryscope/ryscope_themes/{slate,vanilla,glass}.json`, поля `id, name, font, colors, metrics, effects`, 36 цветовых токенов. Бери имена токенов и значения оттуда, не придумывай свои.
* Рисование уже решено в `common/.../ui/Draw.java` (скругления по пикселям устройства со сглаживанием, текст 0.75, стрелки, замок, значок «i») и `ui/theme/Theme.java` (`panel, card, slot, button, input, tab, chip, tooltipBox`, тема `beveled` для Vanilla). В `works.repka.ryscore` повтори эти контракты с теми же именами, чтобы позже слить в одну библиотеку простым переносом.
* Цвета только через токены темы, никаких констант в экранах.
* Выбранная тема должна быть одна на оба мода. Пока RYScore не выделена: если установлен RYScope, следуй его текущей теме (`ui/theme/ThemeManager`, через отражение, без жёсткой зависимости).

**Поведение окон.** Эти решения приняты после жалоб игрока, следуй им с самого начала:

* Окно открывается сразу. Тяжёлый расчёт идёт порциями по несколько миллисекунд за кадр, внутри окна индикатор (`ui/Loading.java`, `runtime/CraftTree.java`).
* Окна не прыгают: верхний край закреплён, рост только вниз (`ui/RecipeScreen.relayout`).
* Никаких длинных подсказок в строке внизу: значок «i» и подсказка при наведении.
* Шапка без лишнего: не дублируй предмет и название, если они уже видны.
* Вкладки вместо стрелок «1/7» там, где страниц несколько (папки закладок в `ui/Overlay.java`).
* Панели обходят чужие области экрана, а не перекрывают их.

**Разметка текста.** Справка RYScope использует `[[item:id]]` и `[[что-угодно:цель|подпись]]` (`docs/09-data-formats.md`). У `ryscore.markup` должен быть тот же синтаксис.

## Связь модов (без жёстких зависимостей)

* **Рецепт из квеста.** Отдельный мост к RYScope не нужен. С RYScope в игре всегда есть JEI, а его `IRecipesGui.show` открывает наше окно (`jei/RyscopeJeiPlugin.java`). Твоего `JeiBridge` достаточно. Превью рецепта в карточке квеста через `IRecipeLayoutDrawable` тоже будет работать.
* **Квесты в рецептах.** Если сделаешь категорию JEI «нужно для квеста», RYScope покажет её сам вкладкой.
* **Важно про потоки.** С RYScope JEI стартует в фоновом потоке `RYScope-JEI`. Твой `onRuntimeAvailable` и регистрация вызываются не из главного потока: не трогай там GL, мир и экраны. Подробности в `runtime/JeiAsync.java`.
* **Стадии как награда.** `/ryscope stage grant <игроки> <id>` работает уже сейчас, id файла из папки сборки это `config:<имя>`. Для начала награды хватит команды.
* **Доска поверх мира.** У RYScope доска целей рисуется слева сверху, `x=4, y=4`, ширина 132 (`runtime/Board.java`), и только когда нет открытого экрана. Твой `StickerBoard` не должен с ней сталкиваться. Сделай его контракт простым: id, высота, отрисовка, приоритет. Я переведу доску целей на него, когда RYScore выделится.
* **Кнопка на панели.** Панель RYScope показывает кнопки из реестра FTB Library. Отдельного реестра для наших модов пока нет: если кнопка нужна, напиши «Запрос к RYScope».
* **Вмешательства RYScope в игру:** `neoforge/src/main/resources/ryscope.mixins.json`. Сверься, прежде чем писать миксин в те же классы.

## Полезное из опыта RYScope

* Самотестирование: `neoforge/.../AutoTest.java` сам создаёт мир, нажимает настоящие клавиши и мышь через отражение, снимает скриншоты и выходит. Сценарии по `-Pautotest=<имя>`. Подход бери, код скопируй к себе.
* Проверка «как у игрока»: `prodtest/build.gradle`. Большую сборку подключай папкой `mods`, не через classpath, иначе Sodium не находится. В dev-запуске нужно выключать игровые тесты NeoForge, иначе падает Binnie Core.
* В больших сборках первым рецептом часто оказывается чужой мод, а моды подмешивают общие таблицы лута. Сверяй поведение на RepYS, не только на чистой игре.
* Версии: NeoForge 21.1.265, Java 21, ModDevGradle 2.0.148, Parchment 2024.11.17, минимальный JEI 19.42.
