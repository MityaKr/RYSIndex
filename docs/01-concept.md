# RYScope: концепт

Самостоятельный мод-конкурент JEI, EMI и REI. Ставится в любую сборку, подхватывает плагины JEI, но выглядит, ощущается и работает иначе. Вайрфреймы всех экранов: `design/concept-page.html`.

## A. Принципы

1. Ноль фризов. Ничего тяжёлого в главном потоке: индекс, поиск, граф, подсчёты строятся в фоне, интерфейс открывается мгновенно и дорисовывается.
2. Контекст важнее списка. Первая сущность не список предметов, а карточка предмета: откуда, зачем, что дальше.
3. Всё данные, не код. Категории, темы, страницы справки, стадии, единицы измерения описываются JSON в датапаках и ресурспаках. Java-API только там, где без него нельзя.
4. Совместимость без компромиссов. Плагины JEI работают через слой совместимости с первого дня (категории Create, Mekanism, AE2 написаны под JEI).
5. Красиво по умолчанию, настраиваемо до мелочей. Темы меняются ресурспаком без перезапуска.

## B. Внешний вид

- Темы: JSON + текстуры в ресурспаке (цвета, рамки слотов, шрифт, скругления, анимации). Встроенные: Slate (по умолчанию), Vanilla Refined, Glass, Paper (для фэнтези-сборок). Подробно: `02-design.md`.
- Плотность: Compact (слоты 16 px, 9 колонок), Comfortable (18 px, подписи категорий), Large (24 px для 4K и игры с дивана).
- Анимации: плавный скролл, подсветка слота, переход между рецептами листанием, мерцание шанса. Одна галочка «без анимаций».
- Раскладка панелей: список справа (классика), два столбца (закладки слева), лента снизу, отдельное окно без инвентаря. Панели перетаскиваются, позиции хранятся по id экрана. Панель уходит, если экран мода занимает её место.

## C. Удобство

- Перенос в рецепт: кнопка переносит ингредиенты в сетку крафта или слоты машины, если экран зарегистрировал передатчик. Shift: максимум.
- Перетаскивание: предмет на панель поиска = фильтр «использует»; на закладки = закрепить; на слот рецепта = подставить вариант ингредиента.
- Умные подсказки: мод, теги, «участвует в N рецептах», «можно скрафтить сейчас», эквиваленты по тегу.
- Клавиатура и геймпад: полная навигация, подписи клавиш, конфликт-детектор горячих клавиш.
- Контекстное меню ПКМ: рецепты, использования, источники, закрепить, в список, сравнить, скопировать id, скрыть.
- Свой масштаб интерфейса независимо от GUI Scale, крупный режим доступности, цветобезопасные метки шанса.
- Карточка предмета: вкладки Рецепты / Использования / Источники / Справка / Граф; ингредиенты в инвентаре подсвечены, недостающие полупрозрачны, строка статуса «8 из 9 есть, не хватает X (есть в сундуке в 6 блоках)».

## D. Фичи

### 01. Граф крафта
Предмет открывается как дерево зависимостей. Узлы сворачиваются; у предметов с несколькими рецептами переключатель прямо в узле; то, что уже есть у игрока (инвентарь, хранилища), помечается и не раскрывается. Внизу считается сырьё, глубина, число станций. Для сборок с прогрессией подсвечивается короткий доступный путь. Shift-клик по корню сворачивает всё, что уже есть. У EMI дерево уже сильное: выбор рецепта в узле, прогресс по инвентарю, батчи, шансы и остатки. Чего у него нет: нескольких деревьев, сохранения между сессиями, учёта хранилищ и подсветки пути по стадиям (см. `05-competitors.md`).

### 02. Линза (фирменная фича, давшая имя)
Зажал клавишу (по умолчанию Alt) и навёл на что угодно: предмет в любом инвентаре, блок в мире, моба, жидкость в баке, предмет в руке другого игрока. Компактная карточка: что это, откуда, короткий рецепт, что в него можно положить, дроп моба с шансами. Клавиши [R] рецепты, [U] использования, [G] граф, Alt+ЛКМ закрепить. Реализуется хуком на рендер подсказки, работает и в чужих GUI.

### 03. Язык поиска
Запросы с подсветкой, автодополнением (Tab) и сохранением пресетов (Ctrl+S). Поиск по всем загруженным языкам одновременно, одна опечатка, транслит.

| Синтаксис | Смысл |
|---|---|
| `@mod` | предметы мода |
| `#tag` | по тегу |
| `uses:X` / `from:X` | где X ингредиент / что делается из X |
| `in:create:pressing` | рецепты категории |
| `drop:mob`, `loot:chest` | источники |
| `craftable`, `almost` | есть всё / не хватает одного |
| `stage:3`, `stage:≤3` | стадия прогрессии |
| `has:nbt`, `has:chance`, `has:fluid` | свойства рецепта |
| `$ingredient` | компоненты (как в JEI) |
| `-слово`, `"фраза"`, `a|b` | исключение, точная фраза, или |

### 04. Источники одной вкладкой
Встроенная замена Just Enough Resources: дроп мобов, лут сундуков и структур, руды по высотам и биомам, торговля жителей, рыбалка, бартер, награды продвижений. Читается из loot-таблиц и worldgen напрямую. API «поставщика источников» для модов с нестандартным дропом (Malum spirit_data, Ars Nouveau).

### 05. Ресурсы первого класса
Абстракция «ресурс»: предмет, жидкость, газ Mekanism, энергия, тепло, вращение Create, мана. У каждого свой рендер, единицы и конвертация. Игрок выбирает единицы энергии (FE/RF/J/EU), все моды показываются в одной. Конвертация в `lens/units/*.json`, моды добавляют свои.

### 06. Доска и список покупок
Закладка это рецепт-стикер поверх мира (HUD, перетаскиваемый). Стикеры складываются в список покупок: сколько сырья нужно, сколько есть в инвентаре, ближайших сундуках, хранилищах модов (AE2, Refined Storage, Sophisticated Storage через API). Прогресс обновляется по мере сборки, список переживает перезаход. Кнопки: запросить в хранилище, в чат, очистить. Клавиши: A закрепить, Shift+A в список.

### 07. Планировщик производства
Цель «N предметов в час» раскладывается по машинам: число машин с учётом времени рецептов, загрузка, энергия, жидкости, узкое место. Режимы: короткий, дешёвый по энергии, только один мод. Экспорт в список покупок. Время и энергия из рецептов и машин, публикующих их через API.

### 08. Сравнение маршрутов
Один предмет, несколько способов в разных модах, рядом в одинаковых единицах: сырьё, время, энергия, побочные продукты, доступность сейчас.

### 09. Прогрессия и замки (опционально для сборок)
Стандарт стадий: тег или датапак, завершённость от поставщика (встроенные продвижения; через API FTB Quests, Game Stages, KubeJS). Закрытый рецепт с замком и ссылкой на условие. Сервер решает видимость: скрытые рецепты не уходят клиенту. Фильтр списка: Доступно / Следующая стадия / Всё.

### 10. Страницы справки
Вкладка «Справка» с лёгким markdown из датапака: иконки предметов в тексте, ссылки на предметы, категории, продвижения, Patchouli и GuideME, предупреждения, 3D-схемы мультиблоков. Моды поставляют справку в jar, сборки переопределяют. Формат:

```json
{ "target": "create:mechanical_crafter",
  "body": [
    { "p": "Многоблочный верстак Create." },
    { "p": "Нужна [[page:create:kinetics|кинетическая энергия]] и [[item:minecraft:redstone]] сигнал." },
    { "warn": "Предметы складываются только по направлению стрелок." },
    { "links": [ {"ponder":"create:mechanical_crafter"}, {"guide":"create:guide#4"} ] },
    { "structure": "create:structures/crafter_3x3" } ] }
```

### 11. Вкладки, история, профили
Назад/вперёд, вкладки открытых предметов, история сессии с поиском. Закладки, пресеты и раскладка в профиле: на мир, на сервер или глобальный, экспорт одним файлом.

## E. Для авторов сборок (dev-режим)

На каждом рецепте вкладка Dev: id, тип, происхождение (какой файл или скрипт KubeJS его создал/переопределил и строка), diff с оригиналом, раскрытие тегов входа, конфликты (тот же вход в той же категории), достижимость от сырья. Кнопки: копировать JSON, копировать KubeJS, открыть файл, перезагрузить.

Глобальные отчёты: недостижимые предметы, конфликты рецептов, циклы с прибылью и рецепты поздних стадий дешевле ранних. Экспорт в CSV/JSON. Плюс экспорт базы рецептов в автономный HTML-сайт для вики, скриншот рецепта в PNG, горячая перезагрузка датапака с подсветкой изменившихся рецептов.

## F. API

Два уровня. JSON-раскладка категории покрывает 80 % случаев без Java:

```json
{ "id": "ryscope:cooking",
  "for": ["minecraft:smelting", "minecraft:blasting"],
  "title": "{recipe.type.name}",
  "size": [120, 40],
  "widgets": [
    { "slot": "ingredient", "at": [4,12] },
    { "progress": "arrow", "at": [28,12], "w": 36, "duration": "{cookingtime}" },
    { "icon": "flame", "at": [40,26] },
    { "slot": "result", "at": [84,8], "large": true } ],
  "footer": "{cookingtime|ticks→s} · {experience} опыта",
  "catalysts": "@recipe-type-blocks" }
```

Java-API для остального:

```java
@RyscopePlugin
public final class CreateRyscopePlugin implements RyscopePluginEntry {
  public void register(RyscopeRegistry r) {
    r.resource(KineticResource.TYPE, new KineticRenderer());
    r.category(PressingCategory.ID, Layout.fromJson("create:ryscope/pressing"));
    r.transfer(MechanicalCrafterScreen.class, new CrafterTransfer());
    r.sources(new PonderSourceProvider());
    r.stageProvider(new AdvancementStages());
    r.units("create:su", Units.of("SU", 1.0));
  }
}
```

Слой совместимости: в MVP мост поверх установленного JEI. RYScope регистрируется как плагин JEI, забирает категории, рецепты, ингредиенты и обработчики переноса из `IJeiRuntime`, а интерфейс JEI подменяет своим (так сделано у EMI). Своя реализация API JEI без самого JEI возможна позже, разбор вариантов: `05-competitors.md`, раздел 1.

## G. Архитектура

1. Снимок: RecipeManager, теги, loot, worldgen, плагины → неизменяемый граф «ресурс → рецепты», пересобирается по событию.
2. Индекс в фоне: имена на всех языках, теги, моды, стадии; UI открывается сразу с полосой «индексация».
3. Кэш на диск: ключ = хэш списка модов + датапаков + языков.
4. Инкрементальность: `/reload` пересчитывает только затронутые узлы.
5. Виртуальный рендер: только видимые слоты, батчинг иконок, кэш подсказок.
6. Сервер решает видимость рецептов и стадии.

Потоки: главный только рендер и ввод; фон: индекс, граф, поиск, планировщик, кэш; сеть: стадии и видимость.

Платформа: NeoForge 1.21.1 первой, собственный тонкий слой абстракции платформы (не Architectury), чтобы Fabric-порт был переносом одного модуля.

## H. Сравнение с конкурентами

| Возможность | JEI | EMI | REI | RYScope |
|---|---|---|---|---|
| Совместимость с плагинами JEI | родная | мост: нужен установленный JEI | нет (заглушка в 16.0.799) | JEI вложен в jar, ставить отдельно не нужно |
| Темы и ресурспак-оформление | нет | 3 стиля сайдбара, подмена PNG | светлая/тёмная, подмена PNG | JSON + текстуры |
| Дерево крафта | нет | есть: выбор рецепта в узле, прогресс по инвентарю, батчи, шансы; одно, не сохраняется | нет | несколько деревьев, сохранение, хранилища, путь по стадиям |
| Линза в мире и в чужих GUI | нет | нет (только стек под курсором в container-экранах) | нет (то же) | да |
| Источники (замена JER) | отдельный мод | нет встроенного | нет встроенного | встроено + API |
| Единая модель ресурсов и единиц | предметы, жидкости | + кастомные стеки; единицы только как формат жидкостей | + кастомные типы; без конвертации | + конвертация единиц, энергия |
| Закладки, «крафтабельно» | закладки | избранное с рецептом, крафтабельно по открытому экрану | избранное, крафтабельно на один уровень | + HUD-стикеры + хранилища |
| Список покупок с подсчётом | нет | частично: режим крафта дерева, не сохраняется | нет | да, с сохранением |
| Планировщик производительности | нет | не найдено | не найдено | да |
| Сравнение маршрутов | нет | не найдено | не найдено | да |
| Стадии с серверной видимостью | нет | нет (тег `c:hidden_from_recipe_viewers`) | нет (тот же тег) | есть: сервер скрывает рецепты и запрещает крафт в сетке |
| Справка с иконками и ссылками | текст | текст + стеки, JSON в ресурспаке | текст, только Java | markdown + схемы |
| Декларативные категории (JSON) | Java | Java; JSON только для свойств и двух типов рецептов | Java | JSON, Java опционально |
| Dev-режим | нет | частично: дубли id, показ id, скриншот рецепта | частично: производительность плагинов, экспорт PNG | происхождение, diff, отчёты |
| Индекс в фоне и кэш на диск | плагины грузятся в главном потоке (замер: 1,15 с на трёх модах) | фон есть, кэша и инкрементальности нет | фон есть, кэша нет | свой индекс и загрузка плагинов JEI в фоне; кэша на диск пока нет |
| Поиск | текущий язык | текущий язык, regex, алиасы | текущий язык, regex, пиньинь | все языки + опечатки + операторы |
| Перенос в слоты | не проверено | свой пакет, без мода на сервере кликами | нужен REI на сервере | + сервер сверяет с рецептом |
| Раскладка панелей | фиксированная | 4 панели с настраиваемыми страницами | слева или справа | перетаскиваемые панели |

Столбцы EMI и REI проверены декомпиляцией 09.11.2026 (EMI 1.1.24, REI 16.0.799), подробности и ссылки на код: `05-competitors.md`. Столбец JEI по коду не проверялся. «Не найдено» значит: отдельным поиском не искали, вывод по косвенным признакам.
