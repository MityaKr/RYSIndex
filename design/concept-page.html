Recipe Lens: вьюер рецептов нового поколения

Самостоятельный мод-конкурент JEI, EMI и REI: ставится в любую сборку, подхватывает плагины JEI, но выглядит, ощущается и работает иначе. Ниже: принципы, внешний вид, удобство, уникальные возможности с макетами экранов, инструменты для авторов сборок, архитектура, совместимость и дорожная карта. Рабочее имя «Recipe Lens», обсуждаемо.

A · Принципы

Пять правил, по которым принимаются все решения

Ноль фризов

Ничего тяжёлого в главном потоке. Индекс, поиск, граф, подсчёты строятся в фоне; интерфейс открывается мгновенно и дорисовывается.

Контекст важнее списка

Игрок редко хочет «список всего». Он хочет понять предмет, в который смотрит: откуда, зачем, что дальше. Поэтому первая сущность не список, а карточка предмета.

Всё данные, не код

Категории, темы, страницы справки, стадии, единицы измерения описываются JSON в датапаках и ресурспаках. Java-API только там, где без него нельзя.

Совместимость без компромиссов

Плагины JEI работают через слой совместимости с первого дня. Иначе мод никто не поставит: категории Create, Mekanism, AE2 написаны под JEI.

Красиво по умолчанию, настраиваемо до мелочей

Из коробки выглядит современно, но каждый может вернуть «ванильный» вид одной темой. Темы меняются ресурспаком без перезапуска.

B · Внешний вид

Темы, плотность, раскладка

У JEI и EMI внешний вид один и зашит в код. Здесь тема — это JSON плюс текстуры в ресурспаке: цвета, рамки слотов, шрифт, скругления, анимации. Четыре встроенные темы, авторы сборок делают свои, игроки переключают в настройках.

C · Удобство

Взаимодействие, которого не хватает

Перенос в рецепт

Клик по «+» на рецепте переносит ингредиенты из инвентаря в сетку крафта или в слоты машины, если экран машины зарегистрировал передатчик. Shift-клик: максимально возможное количество.

Перетаскивание в поиск

Перетащил предмет из инвентаря на панель поиска: фильтр «использует этот предмет». На закладки: закрепил. На слот рецепта: подставил вариант ингредиента.

Умные подсказки

На любом предмете: мод, теги, «участвует в 42 рецептах», «можно скрафтить сейчас», эквиваленты по тегу (все медные слитки разных модов одной строкой).

Клавиатура и геймпад

Полная навигация стрелками и Tab, подписи клавиш на кнопках, поддержка контроллера через стандартные события ввода. Горячие клавиши с конфликт-детектором.

Правая кнопка везде

Контекстное меню на предмете: рецепты, использования, источники, закрепить, в список, сравнить, скопировать id, скрыть.

Масштаб и шрифты

Собственный масштаб интерфейса независимо от GUI Scale игры, чёткий шрифт на любом масштабе, крупный режим доступности с усиленным контрастом и цветобезопасными метками шанса.

Фича 01

Граф крафта

Предмет открывается не страницей, а деревом зависимостей. Узлы сворачиваются; у предметов с несколькими рецептами переключатель прямо в узле; то, что уже есть у игрока, помечается и не раскрывается. Внизу считается сырьё. Для сборок с прогрессией подсвечивается самый короткий доступный путь.

Фича 02

Линза: подсказка где угодно

Фирменная фича, давшая имя. Зажал клавишу (по умолчанию Alt) и навёл на что угодно: предмет в любом инвентаре, блок в мире, моба, жидкость в баке, предмет в руке другого игрока. Появляется компактная карточка с главным: что это, откуда, самый короткий рецепт, что в него можно положить. Не нужно открывать ни инвентарь, ни вьюер.

Фича 05

Ресурсы первого класса: жидкости, газы, энергия, тепло

JEI знает предметы и жидкости, всё остальное моды рисуют сами по-своему. Здесь «ресурс» — абстракция: предмет, жидкость, газ Mekanism, энергия, тепло, вращение Create, мана. У каждого свой рендер, единицы и конвертация. Игрок выбирает, в чём показывать энергию (FE, RF, J, EU), и все рецепты всех модов показываются в одном.

Фича 09

Прогрессия и замки (для сборок, которые этого хотят)

Мод сам не навязывает прогрессию, но даёт стандарт: стадии задаются тегом или датапаком, а завершённость приходит от поставщика (встроенные: продвижения; через API: FTB Quests, Game Stages, KubeJS). Закрытый рецепт показывается с замком и ссылкой на условие. Серверная сторона решает, что видно: скрытые рецепты не уходят клиенту вовсе, так что обойти их ресурспаком нельзя.

E · API

Декларативные категории и Java-API

Два уровня. Для 80 % случаев категория описывается JSON-раскладкой: где слоты, где прогресс, какие поля рецепта куда. Один шаблон покрывает все рецепты с такой формой, и его можно положить в датапак без единой строки Java. Для оставшихся 20 % (кастомный рендер, анимации, интерактив) есть Java-API, плюс слой совместимости для плагинов JEI.

Java-API в двух словах

@LensPlugin
public final class CreateLensPlugin implements LensPluginEntry {
  public void register(LensRegistry r) {
    r.resource(KineticResource.TYPE, new KineticRenderer());        // новый тип ресурса (SU, об/мин)
    r.category(PressingCategory.ID, Layout.fromJson("create:lens/pressing")); // можно и из JSON
    r.transfer(MechanicalCrafterScreen.class, new CrafterTransfer()); // перенос в слоты машины
    r.sources(new PonderSourceProvider());                           // «Источники» из своих данных
    r.stageProvider(new AdvancementStages());                        // поставщик прогрессии
    r.units("create:su", Units.of("SU", 1.0));
  }
}

Слой совместимости: реализация интерфейсов IModPlugin, IRecipeCategory, IRecipeTransferHandler JEI поверх собственного ядра, как это делает EMI. Без него мод никто не поставит, поэтому он в первой же версии.

F · Архитектура

Почему будет быстрее

Внутреннее устройствоклиент + сервер
1. Снимок
RecipeManager, теги, loot, worldgen, плагины → неизменяемый граф «ресурс → рецепты». Пересобирается только по событию.
2. Индекс в фоне
Имена на всех языках, теги, моды, стадии. Отдельный поток; UI открывается сразу с полосой «индексация».
3. Кэш на диск
Ключ: хэш списка модов + датапаков + языков. Повторный вход: читаем индекс, не строим.
4. Инкрементальность
/reload и смена датапака пересчитывают только затронутые узлы графа и их подсказки.
5. Виртуальный рендер
Рисуются только видимые слоты; батчинг иконок одним draw-call-ом на тип; кэш отрендеренных подсказок.
6. Сервер решает
Видимость рецептов и стадии синхронизируются с сервера; клиент не получает то, что ему не положено видеть.
главный поток: рендер, вводфон: индекс, граф, поиск, планировщикфон: кэшсеть: стадии, видимость

Платформа: NeoForge 1.21.1 первой, абстракция платформы с самого начала (свой тонкий слой, не Architectury), чтобы Fabric-порт был переносом одного модуля, а не переписыванием. Минимальная версия Java та же, что у игры.

H · Дорожная карта

Как это строить, чтобы дожить до релиза

Главный риск такого мода не идеи, а объём: конкуренты развивались годами. Поэтому порядок такой, чтобы каждая стадия была полезна сама по себе и ставилась в сборки.

0. Разблокировать сборку

Сейчас maven NeoForge недоступен ни из облака, ни с ПК, и Gradle-проект собрать негде. Варианты: другой выход в сеть для разового скачивания зависимостей, оффлайн-кэш Gradle, перенос в сеть, где maven открыт. Без этого всё остальное остаётся картинками.

1. Ядро + совместимость (MVP)

Граф ресурсов, индекс в фоне, кэш, список предметов, рецепты/использования, слой JEI-плагинов, тема Flat Dark и Vanilla. Цель: заменить JEI в любой сборке без потерь.

2. Фирменные фичи

Линза, граф крафта, язык поиска, источники, доска и список покупок, ресурсы и единицы. Здесь мод начинает отличаться.

3. Для авторов

JSON-категории, страницы справки, dev-режим, стадии с сервером, экспорт в HTML. Привлекает авторов сборок, которые приводят игроков.

4. Расширение

Планировщик, сравнение маршрутов, профили, геймпад, Fabric-порт.

Что проверить до старта

Декомпилировать EMI (слой JEI-совместимости, дерево) и REI, посмотреть, как они решают перенос в слоты и что из «уникального» уже есть. Это день работы с CFR, и он сэкономит недели.

Макеты условные: цвета предметов, цифры и проценты подобраны для наглядности. Названия модов и машин настоящие, поведение их API нужно проверять по коду до реализации.
